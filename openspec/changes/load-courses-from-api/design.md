## Context

学习 feature 的 `cachedLearningPort` 只读取设备本地存储，未使用已存在的认证网络客户端。服务端已经提供受保护的课程目录和详情接口；目录将增加当前内容版本的课时总数，详情仍返回章节与课时。

## Goals / Non-Goals

**Goals:**

- 以 learning feature 内的网络适配器将目录和详情映射为现有课程视图模型。
- 由学习页拥有目录与详情的加载、空态、失败和重试状态；AppShell 仅注入网络依赖。
- 让目录中的课时总数由服务端基于已缓存内容版本计算，客户端不为统计数量而请求全部详情。

**Non-Goals:**

- 不引入查询库、不改服务端契约、不实现离线同步、作业提交或进度展示。

## Decisions

- 在 `features/learning/infrastructure` 新增网络端口，复用 `@services/api` 的认证、超时和错误映射；替代方案是页面直接请求，因越过外部能力边界而拒绝。
- 在课程目录摘要中返回课时总数，并同步 OpenAPI；替代方案是客户端逐门请求详情，因产生 N+1 请求且违反目录只加载摘要的决策而拒绝。
- 目录请求只用于列出课程；点选后再请求详情。这样遵循现有摘要/详情契约，避免把完整内容预载到学习页。
- 页面将用显式状态渲染目录和详情，并在失败时提供重试或返回目录。替代方案是继续显示“正在准备”文案，会掩盖真实请求失败，故不采用。

## Risks / Trade-offs

- [设备无法访问开发机地址] → 使用现有环境配置，并在验收时以 Android 模拟器访问正在运行的后端验证。
- [目录与详情内容版本不一致] → 服务端以目录当前缓存版本关联的章节与课时计算总数，并用集成测试验证。
- [已有本地缓存与服务端内容不同] → 本次以服务端为目录可信源；不覆盖或删除缓存，后续离线能力单独设计。

## Migration Plan

App 更新后直接读取既有 API，无数据迁移。回滚 App 版本即可恢复旧缓存读取行为，服务端保持兼容。
