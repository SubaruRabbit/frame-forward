## Purpose

为持久化表提供可由应用框架稳定识别的实体主键，同时将业务去重约束与技术主键分离，保证存量数据升级后仍然正确且可追溯。

## ADDED Requirements

### Requirement: 持久化表必须具有实体主键

系统 SHALL 为每张业务持久化表定义数据库主键；由应用持久化框架管理的实体 MUST 暴露一个可识别的单列主键。

#### Scenario: 课程进度表完成升级

- **WHEN** 开发环境执行课程进度表的后续数据库迁移
- **THEN** 表具有非空、唯一的单列实体主键

### Requirement: 课程进度业务唯一性保持不变

系统 SHALL 保证同一账户在同一课程内容版本的同一课时最多仅有一条进度记录。

#### Scenario: 重复写入相同课程进度

- **WHEN** 为相同账户、内容版本和课时写入第二条进度记录
- **THEN** 数据库拒绝该重复记录

### Requirement: 存量进度数据可安全迁移

系统 MUST 在不丢失既有课程进度记录的前提下升级表结构。

#### Scenario: 含有既有进度记录的数据库执行迁移

- **WHEN** 迁移运行在已存在课程进度记录的数据库上
- **THEN** 每条既有记录保留其完成时间、业务关联字段和唯一性
