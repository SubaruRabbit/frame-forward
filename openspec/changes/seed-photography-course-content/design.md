## Context

参见 `proposal.md`。现有课程目录在服务端静态定义，数据库只保存内容版本、进度和作业反馈，不能保存或交付 PRD 所要求的章节正文、示例、判断题与实拍任务。受影响范围为 `course`、`bootstrap` 和课程详情的 App 消费端。

## Goals / Non-Goals

**Goals:**

- 将已批准 PRD 的 P0 通用课程和八个首批 Sony/Nikon 机型教程作为可重复执行的 Flyway 种子数据持久化。
- 以课程、章节、课时和课时内容四层结构交付完整内容，并把内容版本、模型、提示词与资料版本关联到种子内容。
- 保持既有进度和作业反馈对内容版本、课时 ID 的关联。

**Non-Goals:**

- 不增加内容编辑后台、视频、即时 AI 生成或相机控制能力。
- 不迁移或伪造已有用户学习进度。

## Decisions

1. 新增课程定义与版本内容表，并在一份递增 Flyway 迁移中插入固定 P0 种子；课程结构以规范化的课程/章节/课时记录保存，课时的正文、正误示例、判断题和作业以结构化 JSON 保存。这样可用稳定课时 ID 保留进度关联，并允许客户端一次读取完整课时内容。备选方案是继续硬编码目录或把整课放入单个 JSON 字段；前者不满足“数据库补全”，后者无法可靠维护章节和课时。
2. 为种子课程的每个课程定义一个不可变内容版本，元数据使用 PRD 基线、`qwen3.7-plus` 与受版本控制的提示词标识；重复执行迁移只由 Flyway 的版本控制保证。备选方案是启动时生成内容，因首次访问依赖 AI 且不可重复而不采用。
3. 扩展课程详情 DTO、OpenAPI 契约和 App 类型以返回章节和课时内容；课程列表仅返回摘要，避免目录请求承载全文。备选方案是复用当前只含目标的 `Lesson`，无法表达 PRD 所需内容。
4. 为每个首批机型建立独立教程，菜单或固件细节仅在受资料版本支持时出现，否则输出“请以相机当前固件和官方说明为准”。

## Risks / Trade-offs

- [大量中文种子文本容易出现 SQL 转义或编码错误] → 使用 UTF-8 迁移、参数边界明确的 JSON，并以迁移集成测试读取校验。
- [新增详情字段可能与 App 契约不一致] → 先更新 OpenAPI 与契约测试，再更新服务端和 TypeScript 类型。
- [修改已存在课程内容会影响已学习版本] → 新内容使用新的内容版本；旧版本和进度不原地覆盖。

## Migration Plan

1. 新增仅向前的课程内容表与 P0 种子迁移。
2. 部署后通过读取课程目录、基础课程和八个机型教程验证种子内容及版本追溯信息。
3. 回滚采用应用版本回退；已执行的 Flyway 迁移不删除课程或进度数据，问题内容通过后续新内容版本修复。
