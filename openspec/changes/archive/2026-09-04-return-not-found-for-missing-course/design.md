## Context

课程服务以同一种缺失课程异常服务课程详情、进度与作业流程。参见 proposal.md 和 delta spec；本次只兑现课程详情端点已声明的 `404` 行为。

## Goals / Non-Goals

**Goals:**

- 将 `GET /courses/{courseId}` 的缺失课程异常映射为 `404 Not Found`。
- 用 HTTP 集成测试锁定该公开响应。

**Non-Goals:**

- 不改变同一服务异常在进度、作业或其他端点中的现有映射。
- 不新增错误响应体契约或修改 OpenAPI。

## Decisions

- 由课程详情控制器在调用课程服务时执行局部异常到 HTTP `404` 的映射；Controller 的协议响应映射职责允许该处理。相比全局 `@RestControllerAdvice` 映射，此方案不会无意改变复用该异常的其他端点。
- 保持现有无响应体的 OpenAPI `404` 声明；新增统一错误体会扩大公开契约，故不在本 change 引入。
- 在 bootstrap HTTP 集成测试中先断言不存在课程的 `404`，再实现映射。相比只测试服务层，集成测试同时覆盖路由、认证和 HTTP 状态。

## Risks / Trade-offs

- [局部映射与其他端点不一致] → 该差异是明确范围边界；后续端点需单独规格化后处理。
- [测试夹具未覆盖认证] → 测试使用有效认证上下文，仅使缺失课程成为决定性条件。

## Migration Plan

- 部署后，客户端可按已发布契约处理 `404`，无需迁移。
- 若出现意外影响，回滚该控制器映射即可恢复原有响应行为。
