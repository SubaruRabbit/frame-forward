## 1. 产品概述

### 1.1 产品名称

中文名称：下一张  
英文名称：FrameForward  
完整品牌名称：下一张 FrameForward  
产品定位副标题：AI微单摄影教练

品牌主张：这一张看见问题，下一张拍得更好。

英文品牌口号：Make your next shot better.

“下一张”表达产品“拍摄、点评、改进、重拍”的成长闭环；“FrameForward”由 Frame 与 Forward 组成，强调让每一个画面持续进步。

### 1.2 产品定位

“下一张 FrameForward”是一款以微单摄影为核心、兼容手机摄影的AI摄影学习与实拍指导应用。

用户可以：

- 系统学习摄影基础和微单操作
- 管理自己的相机、镜头和摄影附件
- 将一台相机设置为主力相机
- 使用手机拍摄当前环境
- 获得适合现有器材的构图、机位、参数和姿势建议
- 查看AI生成的参考照片
- 使用微单完成正式拍摄
- 将作品导入App
- 获得结合画面与EXIF参数的AI评分
- 按照建议重新拍摄并比较进步

### 1.3 核心价值

产品不是简单的照片评分器，也不是手机滤镜工具，而是一名能够理解用户器材和拍摄现场的AI摄影教练。

核心闭环为：

```text
学习摄影知识
    ↓
选择拍摄目标
    ↓
手机采集现场环境
    ↓
AI结合主力相机和器材生成方案
    ↓
用户使用微单完成拍摄
    ↓
导入作品并读取EXIF
    ↓
AI评分与技术诊断
    ↓
根据建议重新拍摄
    ↓
比较作品并记录成长
```

### 1.4 首期平台

- 客户端：Android
- 开发框架：React Native
- 开发语言：TypeScript
- 核心拍摄设备：微单相机
- 辅助设备：OnePlus 11

### 1.5 首发市场

- 首发市场：中国大陆
- 默认语言：简体中文
- 默认时区：北京时间（UTC+8）
- 注册、隐私、图片存储、AI内容和服务接入按照中国大陆市场要求设计
- 首期只确定中国大陆用户体验和服务兼容方向，暂不选择生产部署区域、云资源或正式发布方案

### 1.6 版本结论

本版本是第一版软件开发的需求基线。文中标记为 P0 的能力必须完成并通过第16章验收；P1 和“暂不实现”不阻塞第一版交付。后续若改变产品定位、P0范围、核心数据规则或技术项目边界，必须创建新的PRD版本，不直接修改本批准版。

## 2. 产品目标

### 2.1 用户目标

帮助用户解决以下问题：

- 不会使用微单相机
- 看得懂教程，但不会在真实环境中运用
- 不知道应该使用什么镜头和焦段
- 不知道怎样设置光圈、快门和ISO
- 不知道人物应该站在哪里
- 不知道摄影师应该从哪里拍
- 不会指导人物摆姿势
- 拍完之后不知道问题在哪里
- 不知道下一张照片应该如何改进

### 2.2 业务目标

当前阶段的主要客户和验收者是产品负责人本人。第一版本优先解决个人真实摄影学习与拍摄需求，不以规模化运营、商业化或多人增长为目标。

首期重点验证：

- 用户是否愿意录入和维护自己的摄影器材
- 用户是否愿意根据AI方案实际拍摄
- AI方案是否可以被用户理解和执行
- AI能否结合设备、EXIF和画面提供有效诊断
- 用户是否愿意按照建议再次拍摄
- 重拍后的作品是否获得明显改善
- 摄影课程能否与实拍练习形成闭环

### 2.3 北极星指标

产品负责人每周实际完成以下完整闭环的次数：

> 获得AI拍摄方案 → 使用微单拍摄 → 导入作品 → 获得点评 → 完成至少一次重拍

### 2.4 非目标

首期不以以下能力为核心：

- 专业RAW显影
- 完整照片后期和修图
- 摄影社区
- 摄影比赛与排行榜
- 器材商城
- 商业摄影项目管理
- 对所有相机品牌提供支持
- 取代相机厂商官方控制应用
- 生产环境部署、云资源选型和正式发布方案
- 高可用、弹性扩容、容灾和多环境部署
- 找回密码、重置密码和账号恢复

## 3. 目标用户

### 3.1 核心用户

第一版本的首要用户：

- 产品负责人本人
- 以产品负责人现有设备、拍摄习惯和真实使用反馈作为第一验收标准

未来可以扩展的目标用户：

- 刚购买第一台微单的新手
- 已经拥有微单，但长期使用全自动模式的用户
- 想系统学习摄影的爱好者
- 想提高人像、旅行和生活摄影能力的用户
- 经常帮伴侣、朋友或家人拍照的用户
- 会基础操作，但构图和用光能力较弱的用户

### 3.2 用户能力等级

#### 新手

- 不理解曝光三角
- 不熟悉相机菜单
- 不会选择镜头
- 主要使用自动模式

#### 入门用户

- 理解光圈、快门和ISO
- 会使用光圈优先或快门优先
- 不熟悉复杂光线和构图

#### 进阶爱好者

- 能独立设置参数
- 希望提高审美、用光和表达
- 需要更严格的作品反馈

第一版本重点满足产品负责人本人需求；对外发布时再扩展到新手和入门用户。

- 转接环不属于P0器材类型；用户未明确记录可用转接方案时，AI不得假设镜头可以跨卡口使用。
- APS-C机身使用全画幅镜头时必须计算视角变化；全画幅机身使用APS-C镜头时必须提示裁切或暗角风险。

## 6. 核心用户流程

### 6.1 首次使用

1. 用户打开App。
2. 查看产品介绍。
3. 注册新账号或登录已有账号。
4. 选择摄影经验。
5. 添加相机。
6. 添加镜头。
7. 添加已有附件。
8. 设置主力相机。
9. 选择感兴趣的拍摄类型。
10. 进入首页。

允许用户跳过器材设置，但使用AI现场指导时应再次提醒。

### 6.2 AI现场拍摄指导

1. 用户点击“AI现场指导”。
2. 选择拍摄类型。
3. 确认本次拍摄器材。
4. 默认带入主力相机和常用镜头。
5. 用户使用手机拍摄现场环境。
6. 上传环境照片。
7. AI分析环境、光线、背景和空间。
8. AI生成2～3个拍摄方案。
9. 用户选择一个方案。
10. 查看机位、焦段、参数、姿势和构图提示。
11. 按需生成参考照片。
12. 用户使用微单完成拍摄。
13. 将作品导入App。
14. AI读取EXIF并评分。
15. 用户根据建议重新拍摄。
16. 上传第二张作品。
17. App展示前后对比和进步结果。

### 6.3 独立照片评分

1. 用户点击“上传照片评分”。
2. 从相册或文件系统选择照片。
3. 选择题材或允许AI识别。
4. AI读取EXIF。
5. AI分析画面。
6. 展示评分、优点和问题。
7. 提供重拍建议。
8. 低分作品提供构图参考和示例图。
9. 保存至作品集。

### 6.4 课程学习

1. 用户选择课程。
2. 阅读或观看知识内容。
3. 查看正确与错误示例。
4. 完成互动练习。
5. 接受实拍任务。
6. 上传作业。
7. AI围绕当前知识点评。
8. 更新学习进度。

## 7. 功能需求

### 7.1 账号与用户

#### 功能

- 用户名或邮箱加密码注册
- 密码登录
- 手机号作为可选资料，不要求通过短信验证码验证
- 账号登录状态管理
- 用户资料
- 摄影经验等级
- 感兴趣的摄影题材
- 学习进度
- 数据删除
- 账号注销

#### 账号规则

- 用户名、邮箱在系统内均不可重复；邮箱录入时进行格式校验并统一大小写比较。
- 密码长度为8～64个字符，必须至少包含字母、数字和符号中的两类；日志、接口响应和埋点不得记录密码。
- 用户可以在已登录且再次验证当前密码后修改密码。
- 注册页必须明确提示首期不提供找回密码和账号恢复；忘记密码可能导致账号及数据无法继续访问。
- 登录失败使用统一提示，不暴露用户名或邮箱是否存在；连续异常尝试触发短时技术限流。
- 退出登录后当前刷新会话失效；访问受保护接口时，服务端必须校验登录状态和资源归属。
- 注销账号前必须再次验证当前密码并二次确认。注销成功后，账号、用户资料、器材、课程进度、作品、原图、派生图和AI结果均进入删除流程，且不可通过产品功能恢复。

#### AI使用规则

- 用户必须完成注册并登录后才能使用任何AI功能。
- 首期注册不接入短信验证码，用户通过用户名或邮箱与密码完成注册。
- 密码必须在服务端采用安全的单向散列方式保存，不得存储明文密码。
- AI功能包括现场分析、拍摄方案、参考图生成、照片评分、技术诊断、AI课程生成和AI作业点评。
- 未登录用户只能查看产品介绍、注册页、登录页和明确标记为公开的静态说明；器材、课程、作品及全部AI功能均要求登录。
- 注册用户首期不设置AI使用额度，不展示每日次数或剩余额度。
- 服务端仍保留必要的并发控制、安全限流、异常调用检测和成本观测；这些技术保护不作为面向正常用户的产品额度。

### 7.2 我的器材

#### 相机管理

用户可以：

- 搜索品牌和型号
- 添加多台相机
- 设置一台主力相机
- 修改相机昵称
- 删除相机
- 查看适配教程
- 查看相机能力说明

#### 主力相机规则

- 一个用户只能设置一台主力相机
- 添加第一台相机时默认设为主力相机
- 用户可以随时切换
- 创建拍摄任务时默认选择主力相机
- AI优先基于主力相机生成建议
- 每次拍摄任务允许临时更换相机

#### 镜头管理

用户可以：

- 添加多支镜头
- 设置常用镜头
- 指定镜头与机身组合
- 查看镜头适用场景
- 查看焦段与等效焦距说明

#### 附件管理

支持记录：

- 三脚架
- 闪光灯
- ND滤镜
- CPL滤镜
- 反光板
- 持续灯

AI建议分为：

- 使用已有器材的推荐方案
- 不增加器材的替代方案
- 可选新增器材建议

不得把用户没有的器材作为唯一方案。

课程包括：

- 什么是一张好照片
- 主体与视觉中心
- 画面简化
- 三分法
- 居中构图
- 对称构图
- 引导线
- 框架构图
- 前景、中景和背景
- 留白
- 色彩搭配
- 视觉平衡
- 光线方向
- 硬光和柔光
- 黄金时刻
- 情绪与故事
- 常见构图错误

每节课程包含：

- 核心知识
- 图文或视频说明
- 正确示例
- 错误示例
- 互动判断题
- 实拍任务
- AI作业点评
- 课程总结

#### 课程生成方式

- 首期不建设课程管理后台。
- 课程大纲、章节正文、示例说明、互动题目和实拍任务由AI生成。
- AI模型使用 `qwen3.7-plus`，课程以结构化格式生成并缓存，避免每次打开都重新生成。
- 课程生成必须经过结构校验、重复内容检查、摄影术语一致性检查和安全内容检查。
- 同一课程需要记录生成模型、提示词版本、生成时间和内容版本，便于后续追溯与重新生成。
- 首期不安排人工后台编辑流程；发现问题时通过调整生成规则或重新生成课程处理。
- P0通用课程和首批机型核心教程在验收前批量生成并缓存，避免首次学习时完全依赖即时生成；个性化课程可以按需生成。
- 品牌、型号、菜单路径和固件差异属于高风险事实。生成时必须同时传入受版本管理的器材资料，无法确认的内容必须标注“请以相机当前固件和官方说明为准”，不得编造菜单路径。
- 课程版本一经被用户开始学习，不原地覆盖；重新生成时创建新内容版本，并保留用户原版本的学习记录。
- 课程页提供“内容有误”反馈入口。产品负责人无需使用管理后台，但可以通过重新生成命令或后续开发工具修正内容。

## 8. AI工作流设计

首期使用确定性的Graph/Workflow。

### 8.1 环境分析工作流

```text
读取用户意图
→ 读取主力相机
→ 读取当前镜头
→ 读取已有附件
→ 分析环境照片
→ 判断光线与构图机会
→ 生成候选方案
→ 校验器材可执行性
→ 校验拍摄安全
→ 输出结构化拍摄方案
```

### 8.2 参考图工作流

```text
读取环境分析结果
→ 读取用户选择的方案
→ 生成参考图提示
→ 检查提示内容
→ 调用图像模型
→ 保存结果
→ 返回参考图
```

### 8.3 作品评分工作流

```text
解析文件
→ 提取EXIF
→ 识别照片题材
→ 分析画面质量
→ 分析构图与表达
→ 分析技术参数
→ 对比原拍摄方案
→ 评分校准
→ 生成优缺点
→ 生成重拍建议
→ 输出结构化结果
```

### 8.4 稳定性要求

- AI必须返回结构化数据
- 同一用户、同一图片内容、同一评分规则版本重复提交时复用已有评分结果，避免无意义的分数漂移；用户主动选择“重新分析”时创建新评分版本并明确标注。
- 不允许模型自由修改用户器材信息
- 不允许推荐用户器材无法实现的参数
- 所有参数建议必须经过规则校验
- 拍摄位置必须经过安全检查
- AI输出失败时允许重试
- 工作流节点必须记录耗时、模型和错误信息
- AI任务统一使用 `QUEUED`、`RUNNING`、`SUCCEEDED`、`FAILED`、`CANCELLED` 状态；App重启后通过任务ID恢复状态和结果。
- 工作流输入、结构化输出、提示词版本、规则版本和模型ID均需关联到AI任务，便于复现和问题定位。
- 结构校验失败时最多自动重试2次；仍失败则任务进入 `FAILED`，保留已上传内容并允许用户手动重试，不向用户展示半成品方案或评分。
- 首选模型不可用时，只能切换到配置中已通过同类评测的Qwen备用模型；不得静默切换供应商或能力明显更弱的模型，结果需记录实际模型ID。
- 参考图失败不得阻塞文字拍摄方案；EXIF解析失败不得阻塞纯画面评分。

## 12. 非功能需求

### 12.1 性能

- 普通接口P95响应目标小于500毫秒
- 图片上传需要显示进度
- AI分析期间不得阻塞App操作
- 普通照片分析目标在30秒内完成
- 参考图生成目标在90秒内完成
- 超时任务支持重试和继续查询

### 12.2 可用性

- AI任务失败时保留用户已上传内容
- App重启后可以继续查看任务
- 重复提交需要幂等保护
- 图片生成失败不影响文字拍摄方案
- 页面必须覆盖加载中、空数据、无权限、网络失败、服务失败和重试状态，不允许以空白页表示错误。
- 网络中断时保留尚未提交的表单选择；未完成上传允许用户重新发起，已成功创建的任务不得因重复点击产生重复AI调用。

### 12.3 安全

- 服务端保存AI服务密钥
- App不得直接持有模型密钥
- 上传接口需要鉴权
- 图片使用不可预测的存储标识
- 用户只能访问自己的作品
- 敏感日志不得记录图片地址和个人信息
- 密码使用业界成熟的自适应单向散列算法并带独立盐值；会话凭据支持失效和轮换。
- 服务端校验文件真实类型、大小和可解码性，图片处理设置资源上限，防止伪造文件和解码资源耗尽。

### 12.4 隐私

- 未经授权不将用户照片用于模型训练
- 用户可以删除单张作品
- 用户可以删除所有作品
- 用户可以注销账号
- 上传前清理不必要的定位信息
- 图片首期不设置自动保存期限，默认持续保存，直到用户主动删除图片、清空作品或注销账号
- 隐私政策必须明确说明图片不会自动到期，以及用户可使用的删除入口
- 第一版本不以存储成本作为产品设计约束，不设置因存储成本触发的图片数量、容量或保存时长限制
- 服务端仍记录实际存储用量，供后续版本制定容量和归档策略，但不影响第一版本用户权益
- 人像照片按照敏感用户内容处理
- 用户删除单张作品时，同时删除原图、预览图、参考派生图、结构化EXIF及与该作品绑定的AI结果；共享的器材和课程数据不受影响。
- 删除操作在界面上立即不可见。服务端只有在业务记录与本地文件均删除成功后才返回完成；清理失败必须记录并可重试，不得把“仅隐藏”展示为删除成功。
- 注销账号沿用相同的彻底删除规则。由于首期不提供账号恢复，注销确认后不可撤销。

## 13. 安全与内容规则

AI不得：

- 推荐站在道路中央、悬崖边缘等危险位置
- 鼓励用户进入禁止拍摄区域
- 对人物外貌进行侮辱性评价
- 对身材和身体特征进行价值判断
- 根据照片推断敏感身份
- 将生成参考图描述为真实拍摄结果
- 把艺术评分描述为绝对标准

涉及未成年人照片时，应提供更严格的隐私提示。

## 14. 数据指标

### 14.1 核心指标

- 产品负责人每周完成拍摄闭环的次数

- “AI幻觉”包括虚构器材能力、错误卡口、不可实现参数、无依据的EXIF结论和虚构菜单路径。

### 16.6 端到端验收用例

| 编号 | 验收场景 | 通过条件 |

| E2E-01 | 注册与访问控制 | 使用用户名或邮箱和密码可完成注册，无短信步骤；未登录调用任一AI接口返回未授权，登录后可正常创建AI任务 |
| E2E-02 | 主力器材与兼容性 | 添加首批机身、兼容镜头和附件并设为主力器材后，方案默认使用该组合；不兼容卡口镜头不被作为可执行方案 |

| E2E-04 | 作品评分闭环 | 导入含EXIF的JPEG后获得总分、分项、优缺点、参数诊断和重拍步骤；上传重拍作品后看到具体改善对比 |
| E2E-05 | EXIF降级 | 导入无EXIF的有效JPEG仍能获得画面点评，同时明确展示参数诊断受限和缺失字段 |
| E2E-06 | 任务恢复 | AI任务执行期间关闭并重新打开App，仍能恢复任务状态；失败任务保留上传内容并允许重试 |
| E2E-07 | 评分一致性 | 同一用户对相同图片和评分规则重复提交时返回同一评分版本；主动重新分析时产生可区分的新版本 |
| E2E-08 | AI课程 | 可打开已缓存的基础课程和首批机型教程、完成练习与作业并记录进度；课程内容可追溯模型、提示词和资料版本 |
| E2E-09 | 删除与注销 | 删除作品后原图、派生文件和关联AI结果均不可再访问；注销需验证密码并二次确认，完成后无法登录 |
| E2E-10 | 无恢复能力提示 | 注册和账号设置中明确说明首期不提供密码找回和账号恢复，产品中不存在不可用的找回入口 |

## 17. 主要风险

- 同一照片的AI评分不稳定
- 复杂艺术作品不适合机械评分
- 部分图片缺少完整EXIF
- 不同品牌EXIF字段不完全一致
- 相机菜单随固件版本变化
- 相机和镜头数据库维护成本较高
- 用户器材信息填写错误
- AI参数建议与实际环境存在偏差
- 参考图与现场差异过大
- 图片生成成本较高
- 相机厂商连接协议不统一
- 用户可能误解教程支持等于App可以直接控制相机
